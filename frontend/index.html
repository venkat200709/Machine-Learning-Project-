The project

About RiskRadar

The problem

Safety is not evenly distributed across a city, and it is not constant through the day. The same street can be perfectly safe at 2pm and genuinely dangerous at 2am. Most safety apps only report incidents after they happen. RiskRadar estimates risk before somebody walks into it.

How it works

  1. Raw signals. 29 measurements per area-hour: crime counts by type, lighting condition, CCTV coverage, population density, footfall, distance to police and hospitals, weather and visibility.
  2. Feature engineering. Those become 79 features built on criminological theory — exposure-normalised crime rates, a darkness-exposure term that only activates at night, a surveillance-deficit ratio, and an isolation index.
  3. Ensemble model. A temperature-weighted soft vote over LightGBM, a second wide-tree LightGBM, histogram gradient boosting and logistic regression.
  4. Explanation. Exact Shapley values attribute each verdict back to specific inputs, so the decision can always be challenged.
  5. Prescription. A counterfactual scan reports which realistic intervention would actually lower the risk band.

Honest limitations

  • Trained on a synthetic corpus modelled on Chennai. Before any real deployment it must be refitted on verified municipal crime data.
  • Reported crime is a biased proxy for actual crime — under-reporting is systematic and worst for exactly the offences this project cares about.
  • The model estimates risk; it never identifies people. No personal data is used, stored or transmitted.
  • It must not be used to justify withdrawing services from an area. Predicted risk is a case for investment, not for abandonment.

Uncertainty

A softmax score is the model's opinion. A conformal prediction set is a mathematical guarantee: choose how often you need to be right, and the model returns every band it cannot rule out at that level.
